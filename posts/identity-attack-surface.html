Identity Is the Attack Surface

2025-11-12 · 10 min read Credentials · Token Abuse · Lateral Movement

The security industry has spent decades optimising for the wrong threat model. We scan for vulnerabilities. We patch systems. We rate CVEs by severity and scramble to remediate critical findings before attackers exploit them.

But here's what actually happens in modern breaches: we don't exploit vulnerabilities. We exploit identity.

We don't need a remote code execution bug when we can steal a token. We don't need privilege escalation exploits when delegation is misconfigured. We don't need zero-days when service accounts have domain admin rights and credentials stored in scripts. The attack surface isn't your unpatched servers. It's every identity that has access to something valuable — and in modern enterprises, that's everything.

Why Vulnerabilities Don't Matter Anymore

Let's be clear: vulnerabilities still exist. Software still has bugs. CVEs still get published. But the economics of exploitation have shifted dramatically.

A remote code execution vulnerability requires: finding an exploitable bug, developing a working exploit, bypassing ASLR and DEP, hoping the target hasn't patched, and dealing with EDR that might catch your shellcode.

Credential abuse requires: a valid username and a password, hash, or token. That's it. No exploit development. No memory corruption. No hoping for vulnerable versions.

And the difference in operational success rate is staggering. Exploits fail. Patches break them. Mitigations stop them. But credentials? Credentials work. Every time. Because they're supposed to work.

The Identity Attack Surface

Every modern enterprise has thousands of identities. User accounts, service accounts, admin accounts, emergency access accounts, service principals, managed identities, API keys, OAuth applications, SAML federations. Each one is a potential entry point. Each one has permissions. Each one can authenticate to something. And most of them are over-privileged, under-monitored, and easier to compromise than you think.

Users: The Human Attack Vector

User credentials are the easiest to obtain. Phishing works. Password reuse works. Credential stuffing works. Consent phishing works. AI-generated pretexting works. Once we have a user's credentials, we have email access for intelligence gathering and pivoting, SaaS application access, VPN access for internal network penetration, and often cloud console access depending on role assignments.

A single user account is rarely the objective. It's the foothold. From there, we escalate.

Service Accounts: The Forgotten Keys to the Kingdom

Service accounts are where the real privilege lives. They run automation, CI/CD pipelines, backup jobs, monitoring systems, database replication, API integrations. And they're usually:

  • Over-privileged: Given admin rights because "it made the script work."
  • Poorly protected: Passwords in config files, environment variables, or CI/CD secrets.
  • Unmonitored: No MFA, no conditional access, no anomaly detection.
  • Persistent: Never expire, never rotate, never reviewed.

A service account with domain admin is functionally equivalent to a zero-day — except it never gets patched.

Tokens: The New Password

Modern authentication has moved beyond passwords. OAuth tokens, refresh tokens, SAML assertions, Kerberos tickets, JWT tokens, Azure AD Primary Refresh Tokens (PRTs), session cookies. These aren't "more secure than passwords" — they're just different credentials. And in many cases, they're better from an attacker's perspective:

  • No MFA required: Token theft bypasses MFA entirely.
  • Longer validity: Refresh tokens can last days, weeks, or months.
  • Harder to detect: Token use looks identical to legitimate auth.
  • Easier to exfiltrate: Just strings in memory or on disk.

Passwordless authentication didn't eliminate credential theft. It just changed what we steal.

How We Exploit Identity

The techniques for exploiting identity are well-documented, mature, and reliable.

Initial Access: Getting That First Credential

  • Phishing: Credential harvesting pages that bypass MFA via real-time proxying (Evilginx, Modlishka).
  • Consent phishing: OAuth apps that request permissions users approve without reading.
  • Password spraying: Common passwords against valid usernames — no lockouts if you're careful.
  • Credential stuffing: Breach databases combined with password reuse.
  • OSINT: Credentials in public repos, paste sites, or exposed config files.

Privilege Escalation: Turning Users into Admins

  • Kerberoasting: Request service tickets for any SPN, crack them offline.
  • AS-REP Roasting: Target accounts with pre-auth disabled, crack their hashes.
  • ACL abuse: WriteDACL, WriteOwner, GenericAll on privileged objects.
  • GPO manipulation: Modify Group Policy to add ourselves to privileged groups.
  • Delegation abuse: Kerberos delegation to impersonate high-value accounts.
  • Cloud IAM enumeration: Find over-permissioned roles, escalate through misconfigured policies.

Notice what's missing: memory corruption, exploit chains, kernel bugs. We're abusing how identity and permissions work by design.

Lateral Movement: Spreading Without Exploits

  • Pass-the-hash: NTLM hashes work without knowing the plaintext password.
  • Pass-the-ticket: Kerberos tickets are portable across systems.
  • Token impersonation: Steal tokens from memory, use them to authenticate elsewhere.
  • RDP/WinRM/SMB: Valid credentials authenticate to remote management interfaces.
  • WMI/DCOM: Remote execution with valid credentials — no binaries required.

These techniques don't trigger vulnerability scanners. They don't require patches. They're not CVEs. They're just authentication working as intended.

Persistence: Maintaining Access Through Identity

  • Golden tickets: Forge Kerberos TGTs that grant domain admin for years.
  • Silver tickets: Forge service tickets for specific resources.
  • DCSync rights: Grant ourselves replication permissions to dump credentials whenever we need.
  • Azure AD backdoors: Register devices, add credentials to service principals, create OAuth apps.
  • Service account creation: Create new accounts with high privilege, hide them in service account OUs.

No malware. No rootkits. No files on disk. Just configuration changes and identity abuse that survive reboots, reimaging, and incident response.

Why This Works: The Structural Advantages

Legitimate by Design

When we authenticate with stolen credentials, we're not exploiting anything. We're using the system exactly as designed. Authentication succeeds. Authorization passes. Logs show normal activity. Security tools are optimised to detect abnormal behaviour. But credential use is normal — thousands of authentications occur every minute in an enterprise. How do you alert on "user authenticated successfully" when that's what legitimate users do all day?

Signature Evasion Built-In

EDR and AV look for malicious code. But we're not running malware. We're running PowerShell (built-in, signed by Microsoft), WMI (legitimate Windows management), Azure CLI (official tooling), and native authentication libraries. These tools don't trigger alerts because they're not malicious — they're administrative. And we have credentials that say we're allowed to use them.

Encryption Works Against Defenders

Modern authentication uses encryption for everything. TLS for transport, Kerberos encryption for tickets, encrypted tokens, encrypted API calls. This makes network monitoring nearly useless. We can't see credential theft in transit because it's encrypted. Encryption is a security control — but it's one that prevents visibility into exactly the layer where attacks occur.

Scale Works in Our Favor

Large enterprises have thousands of user accounts, hundreds of service accounts, dozens of admin accounts, complex role assignments, nested group memberships, and forgotten shadow IT. Nobody knows what normal looks like at scale. Nobody can audit every account. Complexity is our cover. The bigger the organisation, the easier it is to hide in the noise.

What Defenders Get Wrong

Focusing on Perimeter Security

Firewalls, IDS/IPS, and WAFs control network boundaries. But we don't attack the perimeter — we authenticate through it. Once we have credentials, the perimeter lets us in. That's what it's designed to do. Zero Trust is supposed to fix this, but in practice, Zero Trust implementations still rely on identity — and if we control identity, we control access.

Trusting MFA Too Much

MFA raises the bar, but it's not a barrier. It can be bypassed via real-time phishing proxies that steal the session token after approval, MFA fatigue attacks (spam push notifications until the user approves one), token theft after authentication, helpdesk social engineering, and legacy protocols (SMTP, IMAP, POP3) that often don't enforce MFA. MFA protects initial authentication. It doesn't protect the session after authentication. And sessions can last hours, days, or weeks.

Assuming Detection Exists

Most organisations assume they'd detect credential abuse. They have SIEM. They have EDR. They have a SOC. But what are they actually detecting? Authentication success logs are too noisy to alert on. Failed logins don't fire because we have valid credentials. Malware signatures don't match because we don't use malware. Exploit attempts don't fire because we don't exploit. Detection is built for what attacks used to look like. It's not built for "user authenticated with valid credentials and accessed authorised resources."

The Real Attack Surface

If identity is the attack surface, then every system that manages, stores, or validates identity is critical infrastructure: Active Directory, Azure AD/Entra ID, IAM systems (AWS IAM, GCP IAM, Azure RBAC), identity providers (Okta, Ping, ADFS), credential stores (Vault, Key Vault, Secrets Manager), endpoints where credentials are entered and tokens are stored, and every application that authenticates users.

Compromise any of these, and you own identity. Own identity, and you own access. Own access, and you own the enterprise. This is why domain controllers are prime targets. This is why privilege escalation focuses on ACLs and delegation rather than exploits. Because once we control the identity layer, we control everything built on top of it.

The Bottom Line

Identity isn't part of the attack surface. Identity is the attack surface.

Vulnerabilities still exist. But we don't need them. Credentials are more reliable, harder to detect, and structurally advantaged against modern defences. Every user account is a potential entry point. Every service account is a potential privilege escalation. Every token is a potential session hijack. Every trust relationship is a potential lateral movement path.

We don't exploit systems. We exploit identity. Because identity is where the access actually lives.
